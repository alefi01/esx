# Корпоративный портал `ftp.domen.pro`

Внутренний веб-портал для двух офисов. Вход по доменным учётным записям
Active Directory, права — по членству в группах AD.

Адреса: `http://ftp.domen.pro/` и короткий `http://ftp/` — оба ведут на один
и тот же сайт (в IIS настроены две привязки).

**Текущее состояние: этап 3 — файловое хранилище.**

## Что уже работает

- Форма входа с проверкой пароля на контроллере домена (LDAP bind)
- Сессия в подписанной cookie, выход из системы
- Роли = группы Active Directory, включая вложенные
- Доступ к порталу только членам группы `WebUsers`, раздел администратора — по группе `WebAdmins`
- Определение офиса пользователя по IP-адресу и выбор ближайшего контроллера домена
- Защита доменных учёток от блокировки перебором через форму входа
- Страница диагностики для администратора: какой IP, какой офис, отвечают ли контроллеры домена
- Заготовка под HTTPS: включается двумя флагами в конфиге, код менять не нужно
- Лента объявлений: публикация по группе `WebPublishers`, правка своего — автором, чужого — администратором
- Текст объявлений хранится как обычный текст, разметка от пользователя не принимается
- Файловое хранилище: дерево папок, права по группам AD с наследованием, загрузка и скачивание
- Пределы размера файла и квоты у каждой папки, автоочистка по сроку, корзина
- Журнал действий: кто что загрузил, скачал и удалил
- Интерфейс как в проводнике: плитки, контекстное меню, Ctrl+C/X/V, перетаскивание файлов
- Загрузка с показом хода выполнения, тёмная тема по системной настройке

## Структура репозитория

```
Portal.sln                        решение (открывается в Visual Studio / Rider)
NuGet.config                      источник пакетов — локальная папка, интернет не нужен
packages/                         .nupkg для сборки без интернета
src/Portal.Web/                   само приложение
  Configuration/                  классы настроек (соответствуют секциям appsettings.json)
  Data/                           сущности, контекст базы и миграции
  Security/                       политики доступа и правила «кто что может»
  Services/ActiveDirectory/       работа с AD по LDAP
  Services/Offices/               определение офиса по IP
  Services/Storage/               файлы, права на папки, фоновая уборка
  Services/Text/                  безопасное превращение текста в HTML
  Pages/                          страницы (Razor Pages)
  wwwroot/                        статика: свой CSS и свой JS, без библиотек
  appsettings.json                настройки, с комментариями
  web.config                      настройки IIS
tests/Portal.Web.Tests/           автотесты (необязательны для развёртывания)
docs/                             документация
```

## Быстрый старт на машине разработки

Нужен .NET SDK 10 (см. [docs/02-что-скачать.md](docs/02-что-скачать.md)).

```powershell
# собрать
dotnet build

# прогнать тесты (нужны пакеты тестов, см. документацию)
dotnet test

# запустить локально на http://localhost:5080
dotnet run --project src/Portal.Web
```

Форма входа будет работать только там, откуда доступны контроллеры домена
`192.168.96.3` или `192.168.112.2`. Без них страница входа откроется,
но выдаст «Контроллер домена сейчас недоступен» — это ожидаемо.
Так же и с базой: без PostgreSQL портал запустится, а раздел объявлений
сообщит о недоступности.

## Основные настройки

Все в `src/Portal.Web/appsettings.json`, файл снабжён комментариями.
Чаще всего меняют:

| Параметр | Что задаёт |
|---|---|
| `ActiveDirectory:AccessGroup` | группа, без которой на портал не пускают |
| `ActiveDirectory:AdminGroup` | группа администраторов портала |
| `ActiveDirectory:BaseDn` | где в каталоге искать пользователей |
| `ActiveDirectory:PublisherGroup` | кто может публиковать объявления |
| `Storage:RootPath` | где на диске лежат файлы |
| `Storage:DefaultMaxFileSizeMb` | предел размера файла по умолчанию (50 МБ) |
| `Offices:Items` | подсети офисов и их контроллеры домена |
| `Security:RequireHttps` | переключатель HTTP → HTTPS |
