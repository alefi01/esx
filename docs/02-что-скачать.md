# Что скачать заранее

В сети нет интернета, поэтому всё переносится вручную. Ниже — минимальный
список для этапа 1 и то, что понадобится дальше.

Проверяйте контрольные суммы после переноса: файлы крупные, а канал между
офисами теряет пакеты.

---

## Обязательно для этапа 1

### 1. ASP.NET Core Hosting Bundle 10.0.10 — на веб-сервер

Это то, что позволяет IIS запускать приложение. Ставится **только на веб-сервер**.

- Страница: <https://dotnet.microsoft.com/download/dotnet/10.0>
- Раздел: **Windows → Hosting Bundle**
- Файл: `dotnet-hosting-10.0.10-win.exe`
- Размер: около 130 МБ

В комплект входит и .NET Runtime, и ASP.NET Core Runtime, и модуль IIS
(`AspNetCoreModuleV2`). Отдельно их качать не нужно.

> Версия Hosting Bundle должна быть **не ниже** той, под которую собрано
> приложение (10.0.10). Более новая — можно.

### 2. .NET SDK 10.0.302 — на машину, где собираете

- Страница: та же
- Раздел: **Windows → SDK x64**
- Файл: `dotnet-sdk-10.0.302-win-x64.exe`
- Размер: около 220 МБ

Собирать можно и на самом веб-сервере — тогда ставьте и SDK, и Hosting Bundle
на него. Это проще всего для первого раза.

### 3. NuGet-пакеты — уже в репозитории

Качать ничего не нужно: файлы лежат в папке `packages/`, а `NuGet.config`
настроен брать пакеты только оттуда. Сборка `src/Portal.Web` проходит
без сети — это проверено с полностью отключённым доступом в интернет.

## Необязательно: чтобы запускать автотесты

Проект `tests/Portal.Web.Tests` для развёртывания не нужен — это страховка
на будущее, чтобы после правок в авторизации сразу видеть, что ничего
не сломалось.

Его пакеты в репозиторий не положены: они занимают около 100 МБ.
Чтобы получить их, на машине с интернетом выполните:

```powershell
git clone <репозиторий> portal
cd portal

# временно вернуть nuget.org
dotnet nuget add source https://api.nuget.org/v3/index.json -n nuget.org

# сложить все пакеты решения в одну папку
dotnet restore --packages .\offline-packages
```

Перенесите папку `offline-packages` на рабочую машину и распакуйте
`.nupkg`-файлы из неё в `packages/`, либо укажите её как источник:

```powershell
dotnet restore --source .\offline-packages
```

Версии пакетов (зафиксированы в `Portal.Web.Tests.csproj`):

| Пакет | Версия |
|---|---|
| Microsoft.AspNetCore.Mvc.Testing | 10.0.10 |
| Microsoft.NET.Test.Sdk | 17.14.1 |
| xunit | 2.9.3 |
| xunit.runner.visualstudio | 3.1.4 |

## Обязательно для этапа 2: PostgreSQL

### PostgreSQL для Windows

- Страница: <https://www.enterprisedb.com/downloads/postgres-postgresql-downloads>
- Версия: **17.x**
- Файл: `postgresql-17.x-windows-x64.exe`, около 350 МБ

При установке снимите галочку со Stack Builder — он полезет в интернет.

> Схема базы и запросы портала проверены на PostgreSQL 16; ничего
> версионно-специфичного в них нет, поэтому 17 подойдёт так же.
> Если по каким-то причинам у вас уже стоит 15 или 16 — тоже годится,
> переустанавливать ради портала не нужно.

Драйвер базы данных отдельно качать не надо: пакеты `Npgsql`
и `Microsoft.EntityFrameworkCore` уже лежат в `packages/` (см. выше).

## Что НЕ нужно качать

Чтобы не тратить время:

- **Node.js, npm, bower** — фронтенд собственной сборки не требует
- **Bootstrap, jQuery** — из проекта убраны намеренно, вместо них один файл CSS
- **Visual Studio** — достаточно SDK и любого редактора; при желании подойдёт
  бесплатный VS Code, но и `dotnet build` в PowerShell хватает
- **IIS URL Rewrite** — редирект на HTTPS делает само приложение
- **Отдельный .NET Runtime** — он уже внутри Hosting Bundle
