# Что скачать заранее

В сети нет интернета, поэтому всё переносится вручную. Ниже — минимальный
список для этапа 1 и то, что понадобится дальше.

Проверяйте контрольные суммы после переноса: файлы крупные, а канал между
офисами теряет пакеты.

---

## Обязательно для этапа 1

### 1. ASP.NET Core Hosting Bundle 10.0.10 — на веб-сервер

Это то, что позволяет IIS запускать приложение. Ставится **только на веб-сервер**.

- Страница: <https://dotnet.microsoft.com/download/dotnet/10.0>
- Раздел: **Windows → Hosting Bundle**
- Файл: `dotnet-hosting-10.0.10-win.exe`
- Размер: около 130 МБ

В комплект входит и .NET Runtime, и ASP.NET Core Runtime, и модуль IIS
(`AspNetCoreModuleV2`). Отдельно их качать не нужно.

> Версия Hosting Bundle должна быть **не ниже** той, под которую собрано
> приложение (10.0.10). Более новая — можно.

### 2. .NET SDK 10.0.302 — на машину, где собираете

- Страница: та же
- Раздел: **Windows → SDK x64**
- Файл: `dotnet-sdk-10.0.302-win-x64.exe`
- Размер: около 220 МБ

Собирать можно и на самом веб-сервере — тогда ставьте и SDK, и Hosting Bundle
на него. Это проще всего для первого раза.

### 3. NuGet-пакеты — уже в репозитории

Качать ничего не нужно: файлы лежат в папке `packages/`, а `NuGet.config`
настроен брать пакеты только оттуда. Сборка `src/Portal.Web` проходит
без сети — это проверено с полностью отключённым доступом в интернет.

## Необязательно: чтобы запускать автотесты

Проект `tests/Portal.Web.Tests` для развёртывания не нужен — это страховка
на будущее, чтобы после правок в авторизации сразу видеть, что ничего
не сломалось.

Его пакеты в репозиторий не положены: они занимают около 100 МБ.
Чтобы получить их, на машине с интернетом выполните:

```powershell
git clone <репозиторий> portal
cd portal

# временно вернуть nuget.org
dotnet nuget add source https://api.nuget.org/v3/index.json -n nuget.org

# сложить все пакеты решения в одну папку
dotnet restore --packages .\offline-packages
```

Перенесите папку `offline-packages` на рабочую машину и распакуйте
`.nupkg`-файлы из неё в `packages/`, либо укажите её как источник:

```powershell
dotnet restore --source .\offline-packages
```

Версии пакетов (зафиксированы в `Portal.Web.Tests.csproj`):

| Пакет | Версия |
|---|---|
| Microsoft.AspNetCore.Mvc.Testing | 10.0.10 |
| Microsoft.NET.Test.Sdk | 17.14.1 |
| xunit | 2.9.3 |
| xunit.runner.visualstudio | 3.1.4 |

## Обязательно для этапа 2: PostgreSQL

### PostgreSQL для Windows

- Страница: <https://www.enterprisedb.com/downloads/postgres-postgresql-downloads>
- Версия: **17.x**
- Файл: `postgresql-17.x-windows-x64.exe`, около 350 МБ

При установке снимите галочку со Stack Builder — он полезет в интернет.

> Схема базы и запросы портала проверены на PostgreSQL 16; ничего
> версионно-специфичного в них нет, поэтому 17 подойдёт так же.
> Если по каким-то причинам у вас уже стоит 15 или 16 — тоже годится,
> переустанавливать ради портала не нужно.

Драйвер базы данных отдельно качать не надо: пакеты `Npgsql`
и `Microsoft.EntityFrameworkCore` уже лежат в `packages/` (см. выше).

## Необязательно: пакеты для сборки виджета

Нужны, только если вы собираете `src/Portal.Client` — настольный виджет.
Порталу они не нужны: он собирается тем, что уже лежит в `packages/`.

**Почему их там нет.** Виджет — самодостаточная программа: один файл,
который работает на ПК без установленного .NET. Чтобы такой файл собрать,
нужен не просто компилятор, а целый рантайм в виде пакетов — около 90 МБ.
Класть их в репозиторий ради программы, которую пересобирают раз
в полгода, — значит утяжелить его втрое для всех, включая тех, кто
виджетом не пользуется.

Без них сборка виджета падает так:

```
error NU1101: Не удалось найти пакет Microsoft.NETCore.App.Runtime.win-x64.
Пакеты с таким идентификатором отсутствуют в следующих источниках: local
```

и то же самое про `Microsoft.WindowsDesktop.App.Runtime.win-x64`,
`Microsoft.NET.ILLink.Tasks`, `Microsoft.AspNetCore.App.Runtime.win-x64`.

**Что сделать.** На машине с интернетом скачайте четыре файла и перенесите
их в папку `packages/` репозитория:

```powershell
# Версия должна совпадать с рантаймом вашего SDK.
# Для зафиксированного в global.json SDK 10.0.110 это 10.0.10.
$v = "10.0.10"

$ids = @(
  "Microsoft.NETCore.App.Runtime.win-x64",
  "Microsoft.WindowsDesktop.App.Runtime.win-x64",
  "Microsoft.AspNetCore.App.Runtime.win-x64",
  "Microsoft.NET.ILLink.Tasks"
)

foreach ($id in $ids) {
  $low = $id.ToLower()
  $file = "$low.$v.nupkg"

  Invoke-WebRequest -OutFile $file `
    "https://api.nuget.org/v3-flatcontainer/$low/$v/$file"
}
```

Скопируйте скачанное в `packages\` — и сборка пойдёт:

```powershell
dotnet publish src\Portal.Client\Portal.Client.csproj -c Release
```

> Проверить, какая версия рантайма у вашего SDK:
> `dotnet --list-runtimes` — нужна строка `Microsoft.NETCore.App 10.0.x`.
> Если там не 10.0.10, подставьте своё число в `$v`.

**`Microsoft.AspNetCore.App.Runtime.win-x64`** самому виджету не нужен —
он попадает в список, если портал собирают самодостаточным
(`dotnet publish -r win-x64 --self-contained`). По инструкции
развёртывания портал собирается обычным способом, и этот пакет
не требуется; качайте его, только если такая ошибка действительно
появилась.

**Другой путь — собрать виджет там, где есть интернет**, и принести
готовый `portal-widget.exe`. Для разовой задачи это быстрее: файл всё
равно кладётся на портал руками (см. `docs/14`), и чем он собран —
на сервере или на ноутбуке администратора, — никакой разницы.

## Необязательно: компонент для настольного виджета

Нужен только если вы ставите сотрудникам виджет на рабочий стол
(см. `docs/14-этап-10-отделы-задачи-виджет.md`), и только ради машин,
где этого компонента нет.

- Страница: <https://developer.microsoft.com/microsoft-edge/webview2/>
- Нужен вариант **Evergreen Standalone Installer, x64** —
  он ставится без интернета
- Файл: `MicrosoftEdgeWebView2RuntimeInstallerX64.exe`, около 150 МБ

Положите файл в папку `App_Data\client` рядом с порталом — туда же,
куда кладёте собранный `portal-widget.exe`. Дальше портал раздаёт его
сам, и только тем машинам, где компонента действительно нет: установщик
виджета сначала смотрит реестр и качает только при надобности.

На Windows 11 компонент входит в систему, на большинстве Windows 10 уже
стоит вместе с Edge. Если все рабочие ПК такие — файл не нужен вовсе.
В репозиторий он не кладётся: 150 МБ в системе контроля версий никому
не нужны.

## Что НЕ нужно качать

Чтобы не тратить время:

- **Node.js, npm, bower** — фронтенд собственной сборки не требует
- **Bootstrap, jQuery** — из проекта убраны намеренно, вместо них один файл CSS
- **Visual Studio** — достаточно SDK и любого редактора; при желании подойдёт
  бесплатный VS Code, но и `dotnet build` в PowerShell хватает
- **IIS URL Rewrite** — редирект на HTTPS делает само приложение
- **Отдельный .NET Runtime** — он уже внутри Hosting Bundle
